## 007 是什么

一个跑在单台服务器上的全能 Agent：接任务、分诊、执行、记账、长记忆，一台机器全包。

- **一个进程干所有活**：网关收信、分诊定路、执行落地、看护巡检、记忆精炼，全部在同一个 Go 进程里，不用拼一堆服务。
- **DeepSeek 驱动，缓存优先**：上下文按缓存友好方式组织，命中缓存的 token 价格只有未命中的 **1/50**，成本先省下来，再谈能力。
- **部署极简**：Go 单静态二进制 + 环境脚本 + systemd 守护，不用 Docker、不依赖容器，拉下来就能跑。

## 快在哪里：分诊 + 三级索引

多数 Agent 一上来就把全部工具说明塞进上下文，token 还没干活就先烧掉一半。007 反过来：

**1. 分诊先行：不需要工具的任务，零工具加载**

- 任务先进分诊：能直接答的直接答，不加载任何工具说明。
- 需要工具才走懒加载：类别 → 子类别 → 具体工具，一层一层取，最多 1–2 次模型调用定位到工具。
- 前缀规则 0 token 先行：固定指令直接命中，不花模型调用。

**2. 三级索引：一次派单的索引成本压到全量的约 1/13**

| 怎么做 | 实测 token |
| --- | --- |
| 全量读 67 个能力文档 | 约 26,601 |
| 走三级索引，一次典型派单 | 约 2,003 |
| **省下的倍数** | **13.3 倍** |

索引分三层，每层都有硬上限，上下文永远不会被索引撑爆：

| 层 | 内容 | 实测上限 |
| --- | --- | --- |
| L1 总览 | 工具总览，常驻 | 214 token |
| L2 分类 | 每类一条工具一行 | 单类上限 760 token |
| L3 详情 | 单个工具的完整用法 | 单份上限 700 token |

上限不是估算，是用 **DeepSeek 官方 tokenizer.json 实测**出来的。索引里没有的工具，分诊不会编造——模型编不出 `tool_id`，因为它根本看不到不存在的工具。

## 稳在哪里：网关 + 监工

**网关：信来了就接住，崩了也不丢**

- 60 秒合并窗口：同一任务的重复来信合并成一次处理，不重复干活。
- `(task_id, inbound_seq)` 去重：同一封信无论来几次，只处理一次。
- 先落盘再回执：信先写进账本数据库，写不进就报错不回执，绝不“收了信却没记账”。
- 崩溃重启能重放：重启后自动把未处理完的信捞回来接着做，实测 kill 掉进程再启动，同一任务的分诊记录不多不少正好 1 条。
- 快慢双车道：短任务走快车道，长任务（>30 秒）转重车道，短任务不等长任务。

**监工 Advisor：只审三个关口，不该管的不管**

- 只在三个关口介入：不可逆动作执行前、长任务分片后、交活前。
- 证据包随身带：每次审查都附上拟执行的命令、目标和上下文（≤3,000 token），不凭空审。
- 最多打回 2 轮：第 3 次仍不通过就直接判停，不无限扯皮。
- 监工自己的花费也进账：每一次审查调用的模型、token、费用都记进账本，监工本身也可审计。

**执行：30 秒内一定有回音**

- 30 秒内能做完的直接做完返回；超过 30 秒的转后台，30 秒内先回一个执行句柄，绝不让调用方干等。
- 超时有硬上限（1,800 秒），超时杀进程组，不留僵尸。
- 环境缺失直接报错：HOME、PATH 等关键环境变量缺了就明确拒绝，不带病执行。

## 记得住：记忆系统

Agent 的价值一半在记忆。007 的记忆不是外挂，是框架自己长的：

- **L1 日志框架内直记**：每一封来信、每一次执行，框架代码直接写进当日 L1 日志，不靠事后扫文件补记，不会漏。
- **每天 04:00 精炼进 wiki**：前一天的 L1 由模型提炼成结构化知识，写进 wiki，L1 只保留最近 7 天。
- **换页 50:1**：会话超过 200,000 token，压成 ≤6,000 字符摘要接着走，上下文不断，成本不炸。
- **召回有上限**：一次最多取 3 条，每条 ≤240 字符，记忆进上下文永远可控，不会越 Recall 越贵。
- **精炼完自动备份**：新增、改动的记忆文件可自动推送备份（默认关闭，自行开启），记忆丢不了。

## 算得清：账本 ledger.db

- 6 张表：分诊指标、索引指标、执行账本、费用账本、队列水位、收信队列。
- 费用按**整数毫分**记账，没有浮点误差，多少就是多少。
- 缓存命中价是未命中的 **1/50**：命中 20 毫分 / 百万 token，未命中 1,000 毫分 / 百万 token，输出 4,000 毫分 / 百万 token（非峰时，峰时 ×2）。
- 每笔费用都带任务号：哪次调用、哪个任务、命中还是未命中，全都能对上账。
- 账本每天 03:30 自动备份，保留最近 7 天。

第一次真实端到端跑通：6 次模型调用，总共 **11 毫分（¥0.011）**——分诊、执行、监工、精炼全走真实模型，不是桩。

## 仓库结构

```
cmd/super-agent/     主程序：网关 + 分诊 + 执行 + 看护 + 记忆，一体启动
cmd/*-verify/        各模块的独立验证程序（影子试跑、端到端回放）
internal/
  config/            环境变量加载（只记键名，不记值）
  gateway/           收信、合并、去重、重放、快慢双车道
  registry/          工具总账：注册、可用性探测、索引读写
  triage/            Tier-0 前缀分诊 + Tier-1 模型分诊
  memory/            L1 日志、wiki、召回、换页、每日精炼
  executor/          直接执行、后台句柄、超时杀组、监工接线
  advisor/           监工：三关口审查、证据包、打回上限
  llm/               DeepSeek 客户端、缓存分区、费用换算
  ledger/            SQLite 账本：6 张表、整数毫分、WAL
  watchdog/          每日巡检、账本备份、记忆精炼调度
  backup/            记忆自动备份（精炼后推送，默认关闭）
step1/               宪法 34 条、工具总账、三级索引等静态家底
```

## 快速开始

```bash
git clone https://github.com/ip9988001/007-super-agent.git
cd 007-super-agent

# 1. 配密钥：建一个 .env，只写这一行
#    DEEPSEEK_API_KEY=你的 DeepSeek API Key
#    （.env 绝不进仓库）

# 2. 编译：Go 1.26，单静态二进制
go build -o super-agent ./cmd/super-agent

# 3. 启动：systemd 托管，监听本地端口收信
./super-agent
```

启动后先看三行日志，确认都就绪：

```
llm ready: model=deepseek-flash
advisor ready: model=deepseek-reasoner
refine loop started: daily 04:00 Beijing
```
