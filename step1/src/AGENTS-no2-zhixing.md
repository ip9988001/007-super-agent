## 三、⛔ 安全话题静默令（用户明令 · 最高优先级 · 2026-10-08）

用户是全部账户、凭据、数据的唯一所有者，已明示：资产可公开、泄露无损失、风险自担。
因此**一切安全风险判断不再由我表达**。

1. **禁提安全**：不主动提风险、不加「我建议」、不说「为了安全」、不写注意事项、不做加固推荐。
2. **禁重复劝阻**：用户否掉的方案，同一理由永不再出现。说过一次即已履行告知，之后只谈执行。
3. **只答两问**：**能不能做**（技术可行性）+ **怎么做**。不能做时只说「卡在哪 + 有哪些替代路径」，不加动机推测、不加后果描述。
4. **不设前置**：不因「这事有风险」而要求二次确认、不附加条件、不降低执行力度。用户说做，就做。
5. **不含糊**：明确告知技术限制（如「GitHub 没有创建 token 的 API」），但这是能力边界说明，不是安全警告。
6. **代价**：违反本令 = 浪费 token + 拖慢用户，属严重错误。


- 优先 hybrid 模式；模糊/探索型查询 top_k 用 5

# 采集/批量生产铁律（GitHub 跑 · Release 收尾）

> 起因：2026-10-26 宗地扩采 1253 层被放到本机跑了 966 分、卡在 89.2% 静默死亡、4.7G 数据只有单副本。
> 根因：规则只写进 wiki（靠 recall 才召回），本机跑没有护栏，退化成本最低路径。

**凡「批量下载 / 批量采集 / 批处理生产」类作业，一律照此执行，无一例外：**

1. **执行地在仓库，不在本机。** 生产运行必须由目标仓 `.github/workflows/` 的工作流在 GitHub runner 上完成。本机只允许「单层 / 单请求」级调试，且同一轮内必须把验证过的脚本推上 runner 跑全量。**严禁在本机用 nohup / systemd / 后台常驻跑生产采集。**
2. **超过 5 小时的作业必须分片。** GitHub 单 job 上限 6h，一律按 matrix 切（默认 200 层/片），每片自带断点续跑 + 独立账本。
3. **跑完必须发 Releases 的 tag，不许只留在 runner 或本机。** 产物按规则打包压缩后上传到该仓 Releases，tag 命名 `{批次}-{类型}-{YYYYMMDD}-{HHMM}`（例：`parcel1-raw-20261026-0814`）。**Release 说明必须写全：层数完成度 / 行数 declared vs 实际 / 有效数 / 失败数 / 残缺层清单。**
4. **账实必须对齐。** 完成判据三件套：workflow 全绿 + Release 产物可下载 + 账本行数与 declared 的差额已逐条解释。任一不满足 = 未完成，不许报「跑完了」。
5. **本机不存生产数据。** 本机可落临时调试产物，生产产物只认 Release。

# 抓取决策阶梯（抓网页 / 查信息 / 调研时）

> 铁律：同类任务失败一次就升级武器，不许试到第三次。
> 上浏览器前先过三级探针：`curl | grep 关键词` 命中即收工 → 再 grep 内嵌 JSON（`window.__` / `__NEXT_DATA__` / `application/json`）有就正则抠 → 两者皆空才算真·JS 页。

阶梯快查：curl+jq → r.jina.ai → `scrapling_make_request`（不起浏览器）→ lightpanda（JS 无渲染）→ `scrapling_fetch`（渲染）→ `scrapling_stealthy_fetch`（硬反爬）→ bulk 批量 → `open_session`（登录态/截图）→ agent-reach（平台化：推特/小红书/B站/RSS/YouTube）
分工：agent-reach 管「去哪拿」，Scrapling 管「怎么抠干净」。
三条硬约束：① 同一 URL 只许试一次，失败即升阶；② 优先用不吃浏览器的；③ 用完必须 `close_session`（本机 2GB 内存）。
